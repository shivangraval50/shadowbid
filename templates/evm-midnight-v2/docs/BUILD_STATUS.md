## Fixed this pass (real bugs found and corrected)

1. **`shadowbid-primitive.test.ts` test-isolation failure** — two tests reused the literal `instanceName: "midnight"`, colliding in `@effectstream/sm`'s process-global `PrimitiveRegistry`. Renamed one; added a regression test asserting the registry's duplicate-name throw (which is correct production behavior and was not weakened).
2. **`LiveMidnightAuctionStateReader` did not actually fail closed on every unreachable-indexer case** — its catch clause only handled `instanceof IndexerError`; a genuinely unreachable endpoint throws a plain `TypeError` from the underlying network client first, which propagated uncaught. Found via `shadowbid-midnight-reader.test.ts` against a real (unbound) port. Fixed by treating any thrown error as `indexer-unavailable`.
3. **`addressToBytes32` / EVM-auction-contract domain encoding was missing entirely** — `shadowbid-coordinator.ts`'s original domain check compared a raw 20-byte EVM address string against a 32-byte Midnight ledger field directly, which can never match. Added the zero-left-pad encoding (documented as a new convention in DECISIONS.md) and fixed the existing test fixtures in `shadowbid-coordinator.test.ts` that had accidentally hidden this by constructing both sides identically.
4. **Missing `@nomicfoundation/hardhat-ignition` symlink** in this worktree's `packages/contracts-evm/node_modules/@nomicfoundation/` (present for its sibling `hardhat-ignition-viem`/`ignition-core`, absent for itself, despite identical declared dependency version `3.0.2`) — this was the actual cause of the previously-reported `Cannot find module '@nomicfoundation/hardhat-ignition/modules'`, not a lockfile or version problem. Repaired by creating the missing symlink (a `node_modules` repair, not a manifest change; does not persist to a fresh install elsewhere).
5. **`ShadowBidAuctionModule` (Ignition) returned `{ auction }` instead of `{ contract }`**, inconsistent with every other Ignition module in the repo; `deploy.ts`'s shared logging reads `result.contract.address` for every deployment, so this threw `TypeError: undefined is not an object` specifically for the ShadowBid deployment step. Renamed to match the established convention.
6. **Two independent bugs in `shadowbid.queries.ts`'s hand-rolled `prepared()` shim**, both invisible until a real database connection actually executed these queries for the first time: an off-by-one in the computed `locs.b` (exclusive vs. the inclusive end `@pgtyped/runtime`'s `replaceIntervals` expects, corrupting `listShadowBidAuctions`'s `LIMIT ... OFFSET ...`), and a regex that matched PostgreSQL's `::type` cast syntax as a named parameter (corrupting `shadowBidServiceState`'s `COUNT(*)::int`). Both fixed; see DECISIONS.md for the exact mechanism.
7. **`contract-shadowbid`'s `--skip-zk` compile flag was not actually required in this environment** — a documented-as-blocked full compile completed in under 2 minutes (subsequently 19.5s) producing all 16 real proving/verifier key files. Switched the default `compact`/`contract:compile` scripts to the real compile; kept `compact:skip-zk` as an explicit escape hatch.
8. **`.gitignore` gaps**: `contract-shadowbid`'s generated `managed/` directory and `contract-shadowbid.*.json` deployment manifest were never excluded (only their `contract-round-value` equivalents were), which became a real risk once the real compile started producing large binary key files. Fixed in both `.gitignore` files.

## Not complete

- The coordinator CLI is a one-shot reference process, not a continuously polling service. It has no multi-party signoff, rate limiting, durable audit trail beyond the result file, or production key-management policy.
- The UI is read-only: wallet-backed mint/list, create, commit, close, open, proving-status, and settlement writes are not implemented.
- Compact does not compute a global maximum or produce a proof consumed directly by EVM. EVM does not directly verify a Midnight ZK winner-computation proof; winner/amount correctness remains a trusted coordinator claim.
- No recorded private three-bidder 8/13/11 run through Midnight winner derivation, EffectStream transition, EVM settlement, and final NFT owner exists.

Do not describe the repository as an end-to-end settlement demo, trustless bridge, or proof-backed auction. EffectStream is deterministic indexing/read-model infrastructure, not settlement authority.
